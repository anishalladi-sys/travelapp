# Prompt 00.2 — Fix Lint Tooling + Typecheck

## Goal
Make `npm run lint` and `npm run typecheck` pass cleanly, and wire them into
the git pre-commit hook.

## Prerequisite
Segment 00.1 marked ✅ in `tasks/README.md`.

## Context
- `npm run lint` currently fails: `next lint` passes legacy options the
  installed ESLint rejects. Verify actual versions first: `package.json` has
  eslint ^8.56 + `eslint-config-next` 15.0.0; a flat `eslint.config.*` may
  exist referencing newer ESLint APIs — diagnose the version/config mismatch
  before choosing the fix (CLAUDE.md anti-hallucination rule).
- `.husky/` contains only `_` — no active hook scripts. `lint-staged` is
  installed but not wired.
- TypeScript errors must be zero after 00.1.

## Tasks
1. Run `npx eslint --version`, `npm ls eslint next eslint-config-next`;
   inspect any `eslint.config.*` / `.eslintrc*` present.
2. Choose the smallest fix that makes lint pass: a correct `.eslintrc` for the
   installed ESLint 8, or a flat config used in an 8-compatible way. Do NOT
   upgrade ESLint major versions as a side effect (dependency upgrades need
   their own justification).
3. Run lint; fix all real findings (no blanket disables; inline comment any
   genuine suppression).
4. Ensure `npm run typecheck` passes.
5. Wire husky pre-commit + lint-staged to run lint + typecheck on staged files.

## Acceptance criteria
- Lint script exits 0 (or only explicitly justified suppressions remain).
- `npm run typecheck` exits 0.
- A deliberately broken staged file is rejected by the pre-commit hook.

## Verification
- `npm run lint`
- `npm run typecheck`
- Invoke the hook/check command directly against an isolated invalid fixture; verify rejection without staging user files or making a commit. Run typecheck project-wide, not only on staged files.

Update `tasks/README.md` segment 00.2 when done.

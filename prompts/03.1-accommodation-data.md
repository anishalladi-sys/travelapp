# Prompt 03.1 — Accommodations: Schema + Data + Actions

## Goal
Add the accommodations module backend: table + RLS, Zod validation, CRUD data
layer, server actions, tests.

## Prerequisite
Phase 02 QA (02.5) marked ✅.

## Context
- Pattern to copy: trips/itinerary in `lib/data/trips.ts`, `app/trips/actions.ts`,
  `lib/validations/`. Dual data mode: Supabase when env vars set, in-memory
  `lib/data/store.ts` otherwise — new module must support both.
- Migrations live in TWO copies (keep in sync): canonical `docs/migrations/`
  + `supabase/migrations/` (used by `npm run db:push`).

## Tasks
1. Zod schema `lib/validations/accommodations.ts`: name (1–200), type enum
   (hotel/hostel/apartment/guesthouse/resort/other), address optional,
   check_in/check_out dates (checkout ≥ checkin), cost optional non-negative
   number, currency (ISO, default from trip), booking_ref optional, contact
   optional, notes optional (≤2000).
2. Migration `accommodations` table: id uuid pk, trip_id fk → trips on delete
   cascade, user_id, name, type, address, check_in, check_out, cost numeric,
   currency, booking_ref, contact, notes, created_at/updated_at. RLS: all ops
   require `auth.uid() = user_id`. Write to BOTH migration copies + update
   `SUPABASE_SETUP.md`.
3. Data layer `lib/data/accommodations.ts`: list/get/create/update/delete,
   ownership-scoped, sorted by check_in. Extend in-memory store equivalently.
4. Server actions `app/trips/[id]/accommodations/actions.ts`: CRUD with Zod
   parse, `requireUserId()`, ownership check, revalidatePath. Errors as
   actionable messages, no stack leakage.
5. Tests: validation edge cases, CRUD against in-memory store, ownership
   isolation (user B cannot touch user A's accommodations).

## Acceptance criteria
- All CRUD works in both data modes; ownership enforced at action + RLS level.
- New tests pass; suite green.

## Verification
- `npm test`, `npm run typecheck`, `npm run build`
- Manual: `npm run db:push` against a dev Supabase project if credentials
  available; otherwise mark that step deferred in the report (do not fake it).

Update `tasks/README.md` segment 03.1 when done.

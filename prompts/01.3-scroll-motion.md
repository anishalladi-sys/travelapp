# Prompt 01.3 — Scroll & Motion Utilities

## Goal
Build the reusable scroll-driven toolkit: Reveal, Parallax, sticky headers,
scroll progress, timeline progress animation — performance-safe and
reduced-motion compliant.

## Prerequisite
Segment 01.2 marked ✅.

## Context
User-approved intensity: "rich scroll storytelling" — but CLAUDE.md gates:
60fps, CLS-safe, `prefers-reduced-motion` respected, mid-range mobile smooth.
No heavy animation library unless genuinely justified (default: CSS +
IntersectionObserver + small rAF helpers). If adding a dependency, justify it
in the segment report.

## Tasks
Create in `components/motion/` + `hooks/`:
1. **`<Reveal>`** — fade/slide/scale-in on first viewport entry. Props:
   direction, delay, stagger (via context for lists). IntersectionObserver,
   unobserve after reveal.
2. **`<Parallax>`** — subtle layered translate on scroll (speed prop). rAF +
   passive scroll listener; disabled when reduced-motion or on low-power mode.
3. **`<StickyHeader>`** — section header that pins while its section is in
   view (position: sticky based, JS only for active-state).
4. **`<ScrollProgress>`** — top progress bar or numeric indicator bound to
   scroll position.
5. **`useReducedMotion`** hook + global: all motion utilities return static
   rendering when set.
6. **CLS safety:** all animated elements reserve final layout space (opacity/
   transform only; never animate layout properties).
7. Unit tests for hooks (reduced-motion path especially).

## Acceptance criteria
- Smooth 60fps scrolling on a test page with 20+ Reveal elements + parallax.
- Zero layout shift from animations.
- `prefers-reduced-motion: reduce` → zero animation (verified in devtools
  rendering emulation).

## Verification
- `npm test` (new hook tests), `npm run typecheck`, `npm run build`
- Devtools: Performance panel scroll trace; Rendering > Emulate prefers-
  reduced-motion.

Update `tasks/README.md` segment 01.3 when done.

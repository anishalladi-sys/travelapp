# Prompt 04.1 — Budget: Schema + Data + Actions

## Goal
Add the expense/budget module backend following the established module pattern.

## Prerequisite
Phase 03 QA (03.5) marked ✅.

## Context
Same module conventions as 03.1/03.3 (dual data mode, two migration copies,
Zod + requireUserId + ownership + revalidatePath).

## Tasks
1. Zod schema `lib/validations/expenses.ts`: category enum (food/transport/
   lodging/activities/shopping/other), description (1–200), amount positive
   number, currency ISO, date (not required to be within trip dates but
   warn-level validated), payment_method optional enum (card/cash/other).
2. Migration `expenses` table: id, trip_id fk cascade, user_id, category,
   description, amount numeric, currency, date, payment_method, timestamps.
   RLS `auth.uid() = user_id`. BOTH copies + setup doc.
3. Data layer `lib/data/expenses.ts`: CRUD + aggregate queries
   (total, by-category totals, by-day totals) computed in the data layer.
   In-memory equivalents.
4. Server actions `app/trips/[id]/budget/actions.ts`: CRUD, same semantics.
5. Optional field: `budget_total` on trips (migration to add column if trip
   settings should carry a budget cap) — include it; nullable, no breakage.
6. Tests: validation, CRUD, aggregates correctness, ownership isolation.

## Acceptance criteria
- CRUD + aggregates correct in both modes; ownership enforced; tests green.

## Verification
- `npm test`, `npm run typecheck`, `npm run build`
- `npm run db:push` if credentials available, else deferred note.

Update `tasks/README.md` segment 04.1 when done.

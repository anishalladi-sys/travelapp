# Prompt 01.4 — QA: Design System

## Goal
Visually and functionally verify the design system (tokens, primitives, motion)
on a committed demo route, fix all defects, and close Phase 01.

## Prerequisite
Segments 01.1–01.3 marked ✅ in `tasks/README.md`.

## Context
Delivered so far: editorial tokens + typography (01.1), core primitives incl.
Timeline (01.2), motion toolkit (01.3). No page uses them yet — Phase 02 does.
The demo route is the design system's permanent living documentation.

## Tasks
1. Create a demo page at `app/design` (clearly labeled, excluded from main nav and search indexing via metadata `robots: noindex`). Confirm with the user before any commit; route visibility is a product decision, not a dev-only guarantee.
2. Populate it: every token swatch, type scale specimen, every primitive in all
   states, Reveal/Parallax/StickyHeader/ScrollProgress live demos, Timeline
   sample, and a reduced-motion demo toggle.
3. QA pass (devtools):
   - Console: zero errors/warnings.
   - Performance: scroll trace with 20+ reveals + parallax stays smooth;
     no forced reflow warnings.
   - CLS: no layout shift as elements reveal.
   - Rendering > emulate `prefers-reduced-motion` → all motion disabled.
   - Keyboard: tab through every interactive element; focus rings visible.
   - Mobile viewport (375px) + desktop (1440px): layout sane at both.
   - Contrast: spot-check ink-on-paper and accent-on-paper text.
4. Fix every defect found. Re-verify.

## Acceptance criteria
- `app/design` demo committed and complete.
- Zero console errors; reduced-motion verified; keyboard-complete; both
  viewports render correctly.
- All four verification commands green.

## Verification
- `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`
- Manual devtools pass as described.

Update `tasks/README.md` segment 01.4 (mark Phase 01 complete) when done.

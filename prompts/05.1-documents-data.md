# Prompt 05.1 — Documents: Schema + Data + Actions

## Goal
Add the travel-documents module backend: metadata-only records (no sensitive
file scans without deliberate encryption).

## Prerequisite
Phase 04 QA (04.5) marked ✅.

## Security context (CLAUDE.md baseline)
Store only metadata + notes in the DB in this phase. Do NOT add document scan
uploads here — ADR-0002 assigns file storage to Cloudflare R2 with signed
URLs; that (with encryption review) is a separate future decision. Expiry
countdowns are computed from metadata only.

## Tasks
1. Zod schema `lib/validations/documents.ts`: type enum (passport/visa/
   insurance/ticket/id/other), title (1–120), number optional (never logged),
   expiry_date optional, notes optional (≤2000).
2. Migration `travel_documents` table: id, trip_id fk cascade, user_id, type,
   title, doc_number, expiry_date, notes, timestamps. RLS
   `auth.uid() = user_id`. BOTH copies + setup doc.
3. Data layer `lib/data/documents.ts`: CRUD, ownership-scoped, sorted by
   expiry (nulls last). In-memory equivalents.
4. Server actions `app/trips/[id]/documents/actions.ts`: CRUD with Zod +
   requireUserId + ownership + revalidatePath. Doc numbers masked in any log.
5. Tests: validation, CRUD, expiry sorting, ownership isolation.

## Acceptance criteria
- CRUD works in both modes; no sensitive values logged; ownership enforced.

## Verification
- `npm test`, `npm run typecheck`, `npm run build`
- `npm run db:push` if credentials available, else deferred note.

Update `tasks/README.md` segment 05.1 when done.

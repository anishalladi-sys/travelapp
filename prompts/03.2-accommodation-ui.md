# Prompt 03.2 — Accommodations UI

## Goal
Build the accommodations UI on the trip page: stay cards, per-night timeline,
booking refs, full state coverage.

## Prerequisite
Segment 03.1 marked ✅.

## Context
- Design system primitives (`components/editorial/`, `components/motion/`,
  Timeline). Tab/section pattern on `app/trips/[id]/page.tsx` — check current
  page structure and choose Tabs (Radix) or section anchors for consistency.
- Server actions from 03.1. Recharts NOT needed here.

## Tasks
1. "Stays" section on trip detail (tab or anchored section, matching the
   itinerary page architecture).
2. Stay cards: name, type badge, date range with nights count, address,
   cost+currency, booking ref with copy-to-clipboard button, contact/notes.
3. Sorted by check-in; Reveal stagger on load; Card + Badge primitives.
4. Add/edit form (Dialog/Sheet): Zod-backed, inline field errors, pending
   state, actionable error messages.
5. Delete: confirm dialog; optimistic remove with rollback.
6. States: empty ("no stays added yet" + CTA), loading skeleton, error with
   retry.
7. Ownership: all mutations via server actions (never client-side filtering).

## Acceptance criteria
- Full CRUD verified in browser in both data modes.
- Keyboard-complete forms; focus management after open/close dialogs.
- Reduced-motion static fallback.

## Verification
- `npm test`, `npm run typecheck`, `npm run build`
- Devtools: CRUD pass, keyboard pass, mobile viewport, console clean.

Update `tasks/README.md` segment 03.2 when done.

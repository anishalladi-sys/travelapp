# Prompt 00.1 — Real Supabase Auth

## Goal
Replace the demo-cookie auth with real Supabase Auth and route the existing
auth code into the app so users can sign up, log in, log out, and only see
their own trips.

## Prerequisite
First segment. No prior segment required. Working tree should be clean-ish
(untracked auth files exist: `app/auth/`, `components/auth-form.tsx`,
`lib/validations/auth.ts`).

## Context (current state)
- Next.js 15 App Router, TS strict, Tailwind (verify effective major version), shadcn/ui, Supabase
  (`@supabase/ssr`), Zod.
- `lib/data/auth.ts` currently returns a demo user via cookie
  `travelapp_user_id` = `demo-user-0001` when no Supabase env vars exist.
- Auth files exist but are unreachable: no page links to them; `auth-form.tsx`
  has multiple typecheck errors (missing `@/components/ui/checkbox` and
  `ui/separator`, wrong `next/link` named import, unused vars, react-hook-form
  generic type errors on lines ~49–173).
- RLS migration exists in TWO locations (keep in sync): canonical
  `docs/migrations/20250101000000_v1_trips_itinerary.sql` (per CLAUDE.md §30)
  and `supabase/migrations/` (used by `npm run db:push`). Itinerary RLS grants
  via parent-trip ownership, not an itinerary `user_id` column.
- Setup docs: `SUPABASE_SETUP.md`.
- `app/auth/actions.ts` references callback/reset URLs that have no routes yet;
  no `middleware.ts` exists yet; login/signup pages do not exist.

## Tasks
1. Fix/complete `auth-form.tsx`: create missing shadcn primitives if absent
   (`ui/checkbox`, `ui/separator`), fix imports and react-hook-form generics,
   remove unused vars.
2. Wire Supabase Auth: email+password and magic link. Create login/signup
   pages, the callback route `app/auth/callback`, and `middleware.ts` for
   session refresh (CLAUDE.md §27 rules apply).
3. Rewrite `lib/data/auth.ts`: `getUserId()`/`requireUserId()` read the Supabase
   session server-side. Keep an in-memory/dev fallback ONLY behind
   `NEXT_PUBLIC_AUTH_MODE=demo` env flag, documented in `.env.example`.
4. Route the flow: `/login`, `/signup` pages; redirect unauthenticated users
   from trips routes; redirect logged-in users away from auth pages.
5. Ownership: verify every trips/itinerary server action and data-layer query
   scopes by `user_id`. Check RLS in BOTH migration copies: trips policies
   enforce `auth.uid() = user_id`; itinerary policies enforce ownership via
   the parent trip (`user_id` on trips). Fix both copies + `SUPABASE_SETUP.md`
   if gaps found, and note the sync requirement.
6. Add auth flow tests (signup validation, login failure, session lookup).

## Acceptance criteria
- Signup → login → create trip → logout → login again → trip still there.
- User B cannot read or mutate User A's trips (verified, not assumed).
- `npm run typecheck` and `npm test` pass.

## Verification
- `npm test`
- `npm run typecheck`
- `npm run build`
- Manual: exercise the auth flow in dev server; attempt cross-user access.

Update `tasks/README.md` segment 00.1 when done.

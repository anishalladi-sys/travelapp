# Prompt 05.4 — Emergency Info UI

## Goal
Add a per-trip emergency information section: curated reference data +
personal contacts, print-friendly, quickly findable.

## Prerequisite
Segment 05.3 marked ✅.

## Context
- Mostly derived/curated content, minimal persistence. Trip has a destination
  field (verify its exact name/values in the trips schema before mapping).
- Local emergency numbers: use an explicitly selected country, not an inference from a free-text destination. Store only entries verified against authoritative country sources, with source references and verification dates, in `lib/data/emergency-numbers.ts`. Unknown countries display an unavailable state and ask the user to verify local services; never guess a fallback number. No runtime external API is needed.

## Tasks
1. Static data file `lib/data/emergency-numbers.ts` (country code →
   police/ambulance/fire numbers) with clear "verify before travel" caveat.
2. Personal emergency contacts: extend trip or a small `emergency_contacts`
   table (trip_id, user_id, name, phone, relation) — follow module pattern,
   RLS, both migration copies, both data modes. Choose the smaller option
   consistent with existing schema; document choice in the segment report.
3. UI: "Emergency" section on trip detail — large, high-contrast numbers,
   insurance hotline (pulled from documents if present), personal contacts
   CRUD, embassy placeholder note ("add embassy info for <destination>").
4. Print-friendly: `print:` styles so this section prints as a clean card.
5. Tests: contacts CRUD + ownership isolation.

## Acceptance criteria
- Section complete with contacts CRUD working both modes; static numbers
  render for the trip's destination; print preview is clean.

## Verification
- `npm test`, `npm run typecheck`, `npm run build`
- Devtools: interaction pass, mobile viewport, print preview check.

Update `tasks/README.md` segment 05.4 when done.

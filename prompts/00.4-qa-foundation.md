## Goal
Functionally verify everything Phase 00 delivered and fix every defect found.

## Prerequisite
Segments 00.1–00.3 all marked ✅ in `tasks/README.md`.

## Context
Phase 00 delivered: real Supabase auth with demo fallback flag, RLS-verified
ownership, working lint/typecheck/build, husky pre-commit, `.env.example`,
strengthened test suite.

## QA procedure (do all)
1. **Automated:** run `npm test`, `npm run lint`, `npm run typecheck`,
   `npm run build`. All must pass.
2. **Auth flow (browser):** signup with a new user → login → logout → login.
   Wrong password shows an actionable error (no stack traces). Magic link flow
   works if configured; otherwise verify it is gracefully hidden.
3. **Ownership isolation (browser or test):** create trips as User A; log in as
   User B; confirm User B cannot see/edit/delete User A's trips via UI **and**
   via direct server-action invocation with A's trip id (this is the check the
   old `authz.test.ts` failed to cover against real actions).
4. **CRUD regression:** create/edit/delete trip, add/edit/remove/reorder
   itinerary item. Date validation edge cases (checkout before checkin, past
   dates per current rules).
5. **Unauth access:** direct navigation to `/trips` and to a specific trip id
   while logged out → redirected to login.
6. Record every defect in a list with severity (critical/major/minor).

## Fix rules
- Fix critical + major defects now, re-verify, and only then mark the phase done.
- Minor defects: fix now if cheap; otherwise record them in
  `tasks/README.md` Notes column with a note pointing at the relevant later
  phase (a11y/06.2, polish/07.2).

## Acceptance criteria
- Zero open critical/major defects.
- All four verification commands green.
- QA results summarized in the segment report.

# Prompt 07.2 — Final Repairs and Reverification

## Goal
Resolve the final audit's defects with regression proof and give an honest release-readiness verdict.

## Prerequisite
07.1 audit completed with its evidence/report linked in `tasks/README.md`. Read `prompts/_CONVENTIONS.md` and `tasks/07-final-qa/README.md`.

## Tasks
1. Read every open audit finding and reproduce it in the recorded local/test fixture. Order by security/data loss, broken workflows, reliability, then UX. Ask before changing scope or architecture; do not discard findings because they are inconvenient.
2. For each defect: add a failing regression at the real action/component/data boundary, verify failure, implement the smallest root-cause fix, then rerun the targeted test. Include adjacent behavior and both data modes where affected.
3. For missing evidence, run the required checks rather than treating absence as a code defect. If credentials/tooling are unavailable, keep the segment blocked with an exact next step.
4. Re-run the complete acceptance matrix, unit/integration/E2E suite, production build, relevant performance traces, accessibility checks, RLS and storage test-environment checks after fixes. Capture failures honestly. The production build currently fails on lint config + `auth-form.tsx` type errors (pre-existing, Phase 00 scope) — 07.2 may only pass if Phase 00 actually fixed them.
5. Update the audit report with resolution/test evidence per finding; update affected canonical docs. Record meaningful repository lessons in an existing `LESSONS.md` if applicable; avoid duplicate history.
6. If the audit found no defects, perform the re-verification and record a no-op repair segment; do not invent cleanup work.

## Acceptance criteria
All audited functional defects resolved and retested, no open critical/major findings, all mandatory checks pass, and any minor carryover explicitly accepted by the user. No automatic commit, merge, push, or deployment.

## Verification
`npm test`, `npm run lint`, `npm run typecheck`, `npm run build`, `npm run test:e2e`, plus all previously failed audit steps and affected hardening checks. Update tracker with evidence and report READY TO SHIP only when every applicable gate is satisfied; otherwise NOT READY TO SHIP with blockers. Stop.

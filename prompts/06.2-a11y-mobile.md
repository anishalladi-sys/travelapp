# Prompt 06.2 — Accessibility and Mobile

## Goal
Make all completed workflows keyboard-accessible, responsive, and aligned with WCAG 2.2 AA.

## Prerequisite
06.1 verified. Read `prompts/_CONVENTIONS.md` and `tasks/06-production/README.md`.

## Files and scope
Inspect shared UI/motion primitives, auth forms, trip forms/detail, all eight modules, global styles, and existing Playwright configuration. Reuse installed accessibility tools rather than assuming a new package exists.

## Tasks
1. Audit representative empty, populated, invalid, pending, and error states at 375, 768, and 1440 CSS pixels; include 200% zoom and narrow reflow.
2. Run automated accessibility checks, then manual keyboard and screen-reader smoke tests. Cover labels/error associations, headings/landmarks, contrast, focus visibility/order, dialog focus return, live announcements, and chart text equivalents.
3. Verify drag reorder has keyboard/button alternatives; gallery and day navigation never trap focus; scroll effects honor reduced motion without hiding content. Provide scroll affordances without hijacking wheel/touch navigation.
4. Fix violations in the narrowest shared component. Maintain >=44px comfortable mobile targets, safe-area spacing, and no page-wide horizontal overflow; allow intentional gallery scrolling.
5. Add regressions for corrected focus/error behavior and rerun affected end-to-end flows. Record tested browser/assistive-technology combinations and limitations in `docs/audits/periodic/`.

## Acceptance criteria
No unresolved applicable WCAG AA violations found by the stated tests; complete mouse-free CRUD flows; readable mobile/reflow layouts; reduced-motion equivalent functionality. Automated scans alone do not establish full compliance.

## Verification
Run `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`, relevant `npm run test:e2e`, automated accessibility scans and manual checks above. Missing required manual tooling is a blocker, not a pass. Apply shared completion procedure and stop.
